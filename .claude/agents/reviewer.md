`git diff`, `git diff --staged`, `git diff main...HEAD`. Читай изменённые файлы целиком, а не только хунки, и связанный код, если нужен контекст.

## Чек-лист (по убыванию важности)

### 1. Надёжность будильника — блокирующее
- [ ] Планирование только через `setAlarmClock`; `PendingIntent` с `FLAG_IMMUTABLE` и уникальным requestCode на alarmId.
- [ ] Любое изменение будильника (создание/правка/тумблер/удаление/snooze/skip) перепланирует или отменяет alarm.
- [ ] Компоненты цепочки звонка `directBootAware`; данные читаются из device-protected storage; нигде в цепочке нет доступа к credential-encrypted storage (обычный `context.filesDir`, `getSharedPreferences` на обычном контексте).
- [ ] Ресиверы: boot, locked boot, time/tz change, package replaced зарегистрированы и вызывают перепланирование.
- [ ] FGS стартует корректно (тип, `startForeground` ≤ 5 с), WakeLock освобождается во всех путях (в т.ч. при исключении).
- [ ] Звук не зависит от жизни Activity; миссию нельзя обойти через Back/Home/Recents/кнопки громкости.
- [ ] Расчёт времени через `java.time` + инжектируемый `Clock`; DST/TZ учтены.

### 1a. Feature flags
- [ ] Новая пользовательская фича закрыта флагом из `config/features.properties` и внесена в реестр PRD §3.12; все её точки входа скрываются при `false`.
- [ ] Выключенная фича не ломает сохранённые будильники (безопасное поведение по FR-FLAG-3).
- [ ] 🔴 Флагом не закрыто ядро (планировщик, ресиверы, сервис звонка, звук, экран звонка, разрешения, хранение) — FR-FLAG-4.
- [ ] Debug-переопределения не попадают в release.

### 2. Корректность
Гонки корутин, отмена `Job`, `viewModelScope`/`lifecycleScope`, утечки Context, nullability, `!!`, обработка ошибок I/O (SAF-URI, битые файлы), миграции Room (есть ли `Migration` и тест).

### 3. Архитектура
Зависимости модулей соответствуют PRD §6.2 (feature → core, не наоборот; feature ↛ feature, кроме `missions:api`); `:core:domain`/`:core:model` без Android; UDF (`UiState` immutable, события вверх); соответствие ADR.

### 4. Compose/UI
Стабильность параметров, отсутствие лишних рекомпозиций (лямбды, `remember`), `collectAsStateWithLifecycle`, токены из `:core:designsystem` (никаких захардкоженных цветов/размеров), строки в `strings.xml` (RU+EN), `contentDescription`, тап-зоны ≥ 48dp.

### 5. Тесты
Есть ли тесты на новую логику; тестируют ли поведение, а не реализацию; нет `Thread.sleep`.

### 6. Безопасность и приватность
`INTERNET` только для погоды (FR-TTS) и сеть не на пути звонка, нет трекеров/аналитики, `exported` только где нужно, нет логирования пользовательских данных, `PendingIntent` immutable.

### 7. Стиль
Kotlin coding conventions, detekt/ktlint, понятные имена, нет мёртвого кода и закомментированных блоков, комментарии объясняют «почему».
