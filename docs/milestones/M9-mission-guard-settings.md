## Цель
Закрыть пробелы защиты миссии, перенесённые из M5 (в M8 они не попали), и дать пользователю глобальные настройки звонка. Язык и тема — вне скоупа (бэклог).

## Архитектура этапа
Подробности — `docs/adr/ADR-021-global-settings-ring-snapshot.md`. Кратко:
* Часть A (защита, R20) — реализация ADR-019 §6–7 и ADR-020 §3–5, новых ADR нет.
* Часть B: `AppSettings` в `:core:model`, `SettingsRepository` в `:core:domain`, реализация на существующем DE DataStore (`app_prefs`, ключи `settings.*`, читается в Direct Boot). `RingingService` берёт снимок настроек на каждый звонок параллельно со стартом звука (≤ 1 с, иначе умолчания) — настройки не на пути к звуку. Изменения применяются со следующего звонка.
* Room v5: `alarm_runtime.ringing_since` (AutoMigration 4→5).
* Диапазоны: автостоп 5/10/15/30/никогда (окно RESUME при «никогда» ≤ 60 мин); бездействие миссии 10–60 с шаг 5 (умолч. 15); приглушение 10–50 % шаг 10 (умолч. 30); первый день недели — по локали / Пн / Вс и т. д.

### M9-T01 — Модель и хранение настроек 🔔
**Описание:** `AppSettings(autoStop, missionIdleTimeout, missionDuckPercent, firstDayOfWeek?)`, `enum AutoStop`; `SettingsPolicy` (диапазоны, умолчания, приведение); `SettingsRepository` + `DataStoreSettingsRepository` (`@Binds`), `ReplaceFileCorruptionHandler`. Флаг `feature.globalSettings=false` в `config/features.properties`.
**Модули:** `:core:model`, `:core:domain`, `:core:data`
**Критерии приёмки:**
- [ ] значения вне диапазона/битый файл → умолчания, без падения;
- [ ] чтение работает в Direct Boot (DE-хранилище);
- [ ] `:core:model`/`:core:domain` без Android-зависимостей.
**Тесты:** unit (политика, приведение), JVM-тест репозитория на DataStore (повреждённый файл). Robolectric-проверка DE-контекста и хэндлера провайдера — в T-test.

### M9-T02 — Маркер `ringing_since` 🔔
**Описание:** схема Room v5 (AutoMigration 4→5, `schemas/5.json`); движок ставит маркер при старте звонка и снимает при snooze/dismiss/skipStale; `rescheduleAll` при маркере в окне `min(autoStop, 60 мин)` ставит RESUME, не затирая `nextTrigger`.
**Модули:** `:core:model`, `:core:data`, `:core:domain`, `:core:alarm`
**Критерии приёмки:**
- [ ] миграция 4→5 сохраняет данные (тест миграции);
- [ ] `APP_LAUNCH` в окне 3 с после падения не затирает RESUME;
- [ ] перезагрузка посреди звонка возвращает звонок.
**Тесты:** Robolectric (миграция, движок во всех путях), R9, R20.

### M9-T03 — Повторный RESUME и `skipMission` 🔔
**Описание:** сервис игнорирует RESUME для уже звонящего будильника; после падения посреди миссии будильник отключается без миссии (ADR-019 §7), событие `MISSION_SKIPPED_AFTER_CRASH`.
**Критерии приёмки:**
- [ ] нет двойного звонка и дублей уведомлений;
- [ ] после `CRASH` в миссии звонок возвращается, миссия пропускается.
**Тесты:** Robolectric (`RingingServiceTest`), R20.

### M9-T04 — Сервис на снимке настроек 🔔
**Описание:** снимок `RingSettings` на звонок (≤ 1 с, иначе умолчания + лог `SETTINGS_DEFAULTED`, звук не ждёт); автостоп из снимка, «никогда» → сессионный WakeLock продлевается каждые 25 мин; приглушение и таймер бездействия из снимка; `missionIdleTimeout` в `RingingState` и превью. Fallback-уведомление без I/O остаётся на 30 мин.
**Модули:** `:core:domain`, `:core:alarm`, `:feature:ringing`
**Критерии приёмки:**
- [ ] автостоп 5 мин срабатывает через 5 мин (виртуальное время) и даёт уведомление «Пропущен»;
- [ ] «никогда»: звонок живёт > 30 мин, WakeLock не истекает;
- [ ] бездействие 30 с и приглушение 50 % применяются в миссии;
- [ ] недоступный DataStore не задерживает звук (≤ 2 с, FR-RING AC).
**Тесты:** unit/Robolectric (виртуальное время), R3, R13, R16.

### M9-T05 — VolumeGuard 🔔
**Описание:** в сессии с миссией сервис раз в 1 с сверяет `STREAM_ALARM` и возвращает целевую громкость, если её понизили (клавиши без фокуса); повышение не трогает; останавливается до восстановления громкости (FR-SND-7).
**Критерии приёмки:**
- [ ] `adb shell input keyevent VOLUME_DOWN` при выключенном экране/без фокуса не понижает звонок надолго;
- [ ] без миссии guard не запускается; лог `VOLUME_GUARD`;
- [ ] R19 (hardening throw) без исключений.
**Тесты:** Robolectric (`ShadowAudioManager`), R17, R19.

### M9-T06 — Recents и SCREEN_OFF 🔔
**Описание:** `RingingActivity.onPause/onResume` → `missionScreenHidden()/Shown()`; сервис через 1 с, если экран скрыт, при включённом экране и не во время вызова — завершает сессию миссии, звук 100 %, экран возвращается (≤ 3 с при overlay). `ScreenOffReceiver` регистрируется в коде только на время сессии миссии: SCREEN_OFF → то же.
**Критерии приёмки:**
- [ ] Recents посреди миссии: звук 100 %, экран звонка возвращается;
- [ ] выключение экрана: звук 100 % сразу, а не по таймеру idle;
- [ ] системный диалог/heads-up/входящий вызов не вызывают ложного завершения миссии.
**Тесты:** Robolectric, R14 (во время миссии), R17.

### M9-T07 — 🎨 Экран настроек «Общие»
**Описание:** автостоп, таймер бездействия, приглушение, первый день недели; RU+EN; токены `:core:designsystem`; секция за флагом `feature.globalSettings`.
**Критерии приёмки:**
- [ ] значения сохраняются и применяются к следующему звонку;
- [ ] флаг выключен → секции нет;
- [ ] TalkBack-метки, поворот/тёмная тема без регрессий.
**Тесты:** Compose UI Test, ViewModel (Turbine).

### M9-T08 — 🎨 Первый день недели
**Описание:** `firstDayOfWeek` параметром в `:core:format` (`null` = по локали), DayChips, список, редактор. На расписание не влияет.
**Критерии приёмки:**
- [ ] порядок дней в чипах соответствует настройке; время срабатывания не меняется;
- [ ] `null` ведёт себя как сейчас.
**Тесты:** unit (`WeekdayFormat`), Compose UI Test.

## Риски
| Риск | Митигация |
|---|---|
| VolumeGuard против восстановления громкости (FR-SND-7) | остановка до восстановления, повышение не трогаем; R19 |
| Ложные `onPause` (multi-window, диалоги, вызов) | проверка через 1 с, отмена в `onResume`, только при включённом экране и не во время вызова; R17, R14 |
| Датчик приближения гасит экран при вызове → ложный SCREEN_OFF | R14 во время миссии |
| Миграция 4→5 ломает данные | AutoMigration + тест, R9 поверх сборки M8 |
| «Никогда» держит WakeLock бесконечно | продление каждые 25 мин, окно RESUME ≤ 60 мин |
| Двойное падение < 60 с снимает alarms (платформа) | известное ограничение, документируется |

## Добавлено по ходу
* T02/T03: `AlarmEngine.restoreRegularPlan` — игнорируемый сервисом RESUME возвращает в `AlarmManager` обычный план (RESUME заменяет его в системе); `setEnabled(false)`/`save(enabled=false)` снимают маркер.
* Ограничения для ADR-019 §7 / ADR-020 §4 (записать в T-docs): (1) `rescheduleAll(APP_LAUNCH)` в окне 3 с после падения перезаписывает crash-RESUME обычным RESUME без `skipMission` — предохранитель теряется; (2) `skipMission` живёт только в extra интента, перезагрузка посреди миссии возвращает миссию; (3) событие пишется как `MISSION phase=skipped_after_crash`; (4) окно RESUME считается от текущей настройки автостопа, а не от снимка звонка.
