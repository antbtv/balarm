## Цель
Пользователь выбирает для будильника встроенную или свою мелодию (импорт через SAF с копированием в device-protected хранилище), задаёт громкость, нарастание и вибрацию, управляет библиотекой. Звонок надёжно играет при любых сбоях источника (цепочка резервов) и корректно выставляет/возвращает громкость `STREAM_ALARM`.

## Архитектура этапа
Резюме architect (детали — ADR-016, ADR-017):
* `Alarm` несёт `SoundSettings(sound: SoundRef, volumePercent 10..100, fadeIn ∈ {0,15,30,60 с})`; `SoundRef` = `builtin:<key>` | `custom:<id>`. На звонке дополнительных чтений хранилища нет.
* Свои мелодии: `DE files/sounds/<id>`, путь вычисляется из id; плеер открывает через `FileDescriptor`. Room v3 (AutoMigration 2→3): колонки в `alarm` + таблица `custom_sound`.
* `:core:alarm`: `AlarmSoundPlayer` (цепочка: выбранная → встроенная `alarm_default` → `ToneGenerator`+вибрация, по 1 с на ступень; нарастание усилением −20 дБ → 0), `AlarmVolumeController` (владельцы RINGING/PREVIEW, чтение обратно, событие `VOLUME_NOT_APPLIED`, исходная громкость в DataStore DE, восстановление только если пользователь не менял).
* Громкость меняется только внутри `RingingService` или видимой Activity (Android 17 игнорирует из фона).
* Новый модуль `:feature:sounds` (пикер и библиотека); `:core:format` — названия встроенных мелодий RU/EN; `:app` — ключи навигации, Result API пикер → редактор.
* Встроенные мелодии (10, CC0) синтезируются офлайн скриптом `tools/sound/generate_builtin_sounds.py` (numpy + libsndfile через ctypes → OGG Vorbis).
* Флаги: новый `feature.alarmSound` (секция «Звук», пикер), существующий `feature.customSounds` (импорт и библиотека). Воспроизведение уже выбранной своей мелодии флагом не отключается (ядро).

## Решения на утверждение
- [x] ADR-016: Мелодии — модель, встроенный каталог, импорт в DE, Room v3 (Proposed)
- [x] ADR-017: Звук звонка — громкость STREAM_ALARM, нарастание, резервы, превью, телефонный звонок (Proposed)
- [x] Правки PRD (вносятся в T-docs):
  1. FR-EDIT-5: шкала громкости 10–100 % (0 % без вибрации = беззвучный будильник, нарушает инвариант).
  2. §6.4: M4 занимает схему v3, R20 («флаг звонит») переезжает в v4; тип `Sound` заменяется моделью ADR-016.
  3. FR-SND-6: «от 10 %» = 10 % амплитуды (−20 дБ), экспоненциальная кривая.
  4. FR-SND-5/FR-RING-1: «≤ 2 с» — штатный путь; при битой мелодии (R15) звук не позже 4 с.
  5. FR-SND-7: громкость восстанавливается, только если пользователь не менял её сам; после падения — отложенно.
  6. §8 строка M4: добавить FR-RING-8 и R14.
  7. ADR-012/§3.7: убрать пункт здоровья `ALARM_VOLUME`.
- [x] Открытый вопрос (решено: только 20 МБ на файл): общий лимит места под свои мелодии. Предложение: только 20 МБ на файл, общий лимит — бэклог.

### M4-T01 — Модель и контракты 🔔 reliability
**Описание:** `BuiltinSound` (10 ключей, `DEFAULT = "alarm_default"` неизменяем), `CustomSoundId`, `SoundRef` (encode/decode, неизвестный ключ → DEFAULT), `CustomSound`, `SoundSettings`; поле `Alarm.sound`. Интерфейсы в `:core:domain/sound`: `SoundRepository`, `SoundFileStore`, `RingVolumeStore`, `SoundPreview`. Флаг `feature.alarmSound=false` в `config/features.properties`.
**Модули:** `:core:model`, `:core:domain`, `config`.
**Критерии приёмки:**
- [x] Модель и домен без Android-зависимостей
- [x] `SoundRef.decode(encode(x)) == x`; мусор/неизвестный ключ → DEFAULT
- [x] `volumePercent` ограничен 10..100, fadeIn — из допустимого набора
- [x] Флаг добавлен со значением `false`
**Тесты:** unit: SoundRef, SoundSettings.

### M4-T04 — Репозиторий мелодий 🔔 reliability
**Описание:** импорт SAF → tmp с подсчётом байт (лимит 20 МБ) → проба `MediaExtractor`/декодер → транзакция → rename в `DE files/sounds/<id>`; rename; удаление одной транзакцией с переключением будильников на DEFAULT и возвратом их числа; `usageCount`; `cleanUp` осиротевших файлов; отмена, нехватка места. `RingVolumeStore` на DataStore `app_prefs` (DE).
**Модули:** `:core:data`.
**Критерии приёмки:**
- [ ] Файл > 20 МБ и не-аудио отклоняются с типизированной ошибкой, tmp удаляется
- [ ] Удаление используемой мелодии переключает будильники на DEFAULT атомарно
- [ ] Файл лежит в device-protected хранилище
- [ ] `cleanUp` удаляет файлы без записи и записи без файла
**Тесты:** Robolectric: импорт/лимит/отмена/удаление/cleanUp.

### M4-T05 — Плеер 🔔 reliability
**Описание:** `AlarmSoundPlayer.start(settings, fadeIn, onFallback)`, `setMuted`, `stop`. Источник по `SoundRef` (raw или FD файла). Цепочка с таймаутом 1 с на ступень: выбранная → DEFAULT → `ToneGenerator`+вибрация. Нарастание −20 дБ → 0, не применяется для RESUME/CATCH_UP/раннего звука сторожа. События `SOUND_STARTED source=…`, `SOUND_FALLBACK`.
**Модули:** `:core:alarm`.
**Критерии приёмки:**
- [ ] Удалённый/битый файл → играет DEFAULT; если и он недоступен — тон+вибрация
- [ ] Худший случай до звука ≤ 4 с (R15)
- [ ] Нарастание начинается с 10 % амплитуды и достигает целевого за выбранное время
- [ ] `USAGE_ALARM`, `AudioFocus` как в ADR-008
**Тесты:** unit цепочки (фейки), нарастания (кривая); Robolectric. Сценарии: R15.

### M4-T06 — Громкость STREAM_ALARM 🔔 reliability
**Описание:** `AlarmVolumeController` (acquire/release, владельцы RINGING/PREVIEW, один снимок исходной громкости на всех), установка → чтение обратно → `VOLUME_NOT_APPLIED`; перехват `IllegalStateException`; исходная громкость — в `RingVolumeStore`; восстановление только если текущая == выставленной; `restorePendingIfIdle()` на APP_LAUNCH; интеграция в `RingingService` (RESUME без нарастания, очередь, восстановление до `stopIfIdle`).
**Модули:** `:core:alarm`.
**Критерии приёмки:**
- [ ] Громкость 1 → звонок на выставленном % → после остановки снова 1 (R11)
- [ ] Если пользователь изменил громкость во время звонка — не перезаписывается
- [ ] После падения процесса исходная громкость восстанавливается при следующем запуске/звонке (R20)
- [ ] Очередь будильников (R13) не теряет исходную громкость
**Тесты:** unit/Robolectric с фейковым `AudioManager`. Сценарии: R11, R13, R19, R20.

### M4-T07 — Режим аудио (FR-RING-8) 🔔 reliability
**Описание:** слушатель режима аудио: при телефонном звонке — mute + вибрация, после — возобновление с нарастанием 15 с.
**Модули:** `:core:alarm`.
**Критерии приёмки:**
- [ ] Входящий вызов не ломает сервис; после вызова звук возвращается
- [ ] Вибрация идёт, пока звук приглушён
**Тесты:** unit. Сценарии: R14.

### M4-T08 — Превью 🔔 reliability
