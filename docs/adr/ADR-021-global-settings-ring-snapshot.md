# ADR-021: Глобальные настройки звонка: хранение в DE DataStore, снимок на звонок, автостоп «никогда»

## Status
Accepted (M9, 2026-10-14; предложен 2026-10-13, план M9). Заменяет константы `RingingPolicy.AUTO_STOP_AFTER`, `MissionPolicy.IDLE_TIMEOUT`, `MissionPolicy.DUCK_GAIN` настраиваемыми значениями (они становятся значениями по умолчанию). Уточняет ADR-007 §5 (автостоп, сессионный WakeLock), ADR-019 §4/§8 (таймер бездействия, приглушение), ADR-020 §4 (окно RESUME). ADR-001 не меняется.

## Context
* PRD §3.9, FR-RING-6 (автостоп 5/10/15/30 мин/никогда), FR-MIS-2 (приглушение 30 % «настраиваемо», бездействие 10–60 с), первый день недели (сейчас `WeekFields.of(locale)` в `:core:format`). Язык и тема — вне M9.
* Три значения нужны цепочке звонка, в т.ч. в Direct Boot (звонок после ночной перезагрузки до разблокировки — R3) и в `rescheduleAll` на `LOCKED_BOOT_COMPLETED` (окно RESUME, ADR-020 §4).
* В `:core:data` уже есть один `DataStore<Preferences>` на DE (`datastore/app_prefs.preferences_pb`, ADR-001 §1–2), его используют `SetupStateRepository` и `RingVolumeStore`. Отладочные флаги (FR-FLAG-5) — SharedPreferences на DE ради синхронного чтения.
* Звук стартует до решения движка (сторож 2 с, ADR-007 уточнения §2); настройки не должны задерживать звук.
* «Никогда» конфликтует с таймаутом сессионного WakeLock (автостоп + 1 мин) и с окном RESUME (`now − ringingSince < AUTO_STOP_AFTER`).

## Decision
1. **Хранение — существующий DE DataStore**, ключи с префиксом `settings.*`. Отдельного файла и SharedPreferences не вводим: ни одному читателю не нужно синхронное чтение (см. п. 4–5). Значения вне допустимого диапазона и битые → значение по умолчанию (coerce в маппере); у DataStore — `ReplaceFileCorruptionHandler` → пустые prefs (вместо исключения при чтении в цепочке звонка).
2. **Модель** (`:core:model`): `AppSettings(autoStop: AutoStop, missionIdleTimeout: Duration, missionDuckPercent: Int, firstDayOfWeek: DayOfWeek?)`; `enum AutoStop { MIN_5, MIN_10, MIN_15, MIN_30, NEVER }`. Диапазоны и умолчания — `SettingsPolicy` в `:core:domain`: автостоп 30 мин; бездействие 10–60 с, шаг 5, по умолчанию 15; приглушение 10–50 %, шаг 10, по умолчанию 30; `firstDayOfWeek = null` — по локали.
3. **Контракт** (`:core:domain`): `interface SettingsRepository { val settings: Flow<AppSettings>; suspend fun update(transform: (AppSettings) -> AppSettings) }`. Реализация `DataStoreSettingsRepository` в `:core:data`, `@Binds` в `DataModule`. Зависит только от `DataStore` (и `FeatureFlagProvider`, п. 7) — не от движка, планировщика или контроллера, поэтому циклов в графе Hilt нет: `RingingService`/`AlarmEngine` → `SettingsRepository` → `DataStore`. Изменение настроек ничего не перепланирует.
4. **Снимок на звонок.** `RingingService` при старте каждого звонка очереди читает `settings.first()` под `withTimeoutOrNull(1 с)`, параллельно решению движка; таймаут/ошибка → умолчания, событие `SETTINGS_DEFAULTED`. Снимок `RingSettings(autoStop, idleTimeout, duckGain)` действует до конца этого звонка; изменения в настройках во время звонка применяются со следующего. Таймер автостопа запускается от начала звонка после получения снимка (опоздание ≤ 1 с не значимо). `RingingState.Ringing` публикует `missionIdleTimeout`, чтобы полоска бездействия на UI и таймер сервиса совпадали; превью миссии в редакторе читает репозиторий.
5. **Автостоп «никогда».** Таймер не ставится; сессионный WakeLock берётся с таймаутом 30 мин и продлевается сервисом каждые 25 мин, пока идёт звонок (WakeLock без таймаута не используем). Fallback-уведомление при отказе FGS (ADR-007 §6) сохраняет константу `setTimeoutAfter(30 мин)`: ресивер не делает I/O до старта FGS.
6. **Окно RESUME (ADR-020 §4)** = `min(autoStop, RingingPolicy.RESUME_WINDOW_CAP = 60 мин)`, для `NEVER` — 60 мин. Движок читает настройку тем же способом (п. 4, умолчание при сбое). Звонок, начатый больше часа назад, после перезагрузки не возобновляется — маркер очищается, далее обычный план и уведомление о пропуске (M7).
7. **Флаг** `feature.globalSettings` (FR-FLAG): скрывает секцию в настройках; при выключенном флаге репозиторий отдаёт умолчания (сохранённые значения не удаляются). Ядро звонка флагом не закрывается — оно всегда работает от `AppSettings`, просто с умолчаниями.
8. **Первый день недели** — только UI: ViewModel-и списка/редактора кладут `firstDayOfWeek` в `UiState`, `:core:format` получает его параметром (`null` → локаль). На расписание и `NextTriggerCalculator` не влияет.

## Alternatives considered
* **SharedPreferences на DE (как debug-флаги)** — синхронное чтение, но второй механизм хранения настроек; синхронность никому не нужна (п. 4–5). Отклонено.
* **Отдельный файл DataStore `settings`** — изоляция, но второй экземпляр под квалификатором и второй файл для бэкапа (ADR-005). Отклонено: префикса ключей достаточно.
* **Настройки «на будильник» (в Room)** — Alarmy так делает частично, но это миграция и UI редактора; PRD требует глобальные. Отклонено.
* **Живое применение настроек посреди звонка** — сложнее (перезапуск таймеров) без пользы. Отклонено.
* **Бесконечное окно RESUME при «никогда»** — звонок «оживает» через сутки после перезагрузки. Отклонено.

## Consequences
* (+) Константы уходят из 6 мест (`RingingService`, `RingingWakeLocks`, `MissionFrame`, `MissionPreview`, тесты); значения в одном источнике.
* (+) Direct Boot: DataStore уже на DE — R3 покрывается по построению.
* (−) `ReplaceFileCorruptionHandler` общего `app_prefs` при повреждении файла сбрасывает всё: настройки, онбординг и сохранённую громкость (ADR-017) — редкий компромисс единого файла; без обработчика хранилище навсегда ломало запись.
* (−) Лишнее чтение DataStore на каждый звонок (мс; не на пути к звуку).
* (−) «Никогда» = звонит до разряда/отключения: осознанный выбор пользователя; в UI — пояснение.
* Проверка: unit — coerce диапазонов, `NEVER`, окно RESUME с cap; Robolectric — репозиторий на DE-контексте, битый файл → умолчания, сервис: автостоп 5 мин, `NEVER` + продление WakeLock, таймаут чтения → умолчания, idle/duck из снимка; эмулятор — R3 с автостопом 5 мин, R13 (свой снимок у каждого звонка очереди), R16 с бездействием 30 с.
