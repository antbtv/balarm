## Цель
Минимальная рабочая миссия Math: настройка в редакторе (уровень, количество), превью, прохождение на звонке. Всё, что не нужно для «нельзя отключить без миссии», вынесено из этапа (см. «Перенесено»).

## Урезано относительно первой версии плана
Вне M5: маркер `ringing_since` и R20-RESUME (остаётся известным риском), `VolumeGuard`, `skipMission`, Hilt-мультибиндинг реестра (в MVP одна миссия — лёгкий интерфейс в `:feature:missions:api`), отдельный `MissionSettingsRoute`, иконка миссии в карточке, сохранение черновика редактора, экран настроек таймера (константы). ADR-018/019/020 остаются Proposed и уточняются в T-docs; писать новые не нужно.

## Архитектура этапа (кратко)
* Модель: `Alarm.mission: MissionSpec?` (`type` + JSON-конфиг), Room v4 (AutoMigration 3→4, только колонки миссии). Флаг `feature.mission.math` выключен → `effectiveMission = null`, будильник отключается без миссии.
* `RingingService` ведёт сессию миссии: приглушение усилением `MediaPlayer` до 30 %, таймер бездействия 15 с (→ 100 % и сигнал сброса), `ACTION_DISMISS` с миссией отклоняется, пропал UI → сразу 100 %.
* `RingingActivity` — хост: «Отключить» → миссия; Back → назад на звонок (звук громко); возврат экрана ≤ 3 с после Home.
* Math: `MathGenerator(Random)` (чистый Kotlin), `MathConfig(level 1..5, count 1..10)`, по умолчанию 2 и 3.

### M5-T01 — Модель, домен, Room v4 🔔
Модели в `:core:model`, `MissionCatalog`/`effectiveMission`/`MissionPolicy` (15 с, 0,3) и команды `RingingController` в `:core:domain`, колонки миссии и AutoMigration 3→4 в `:core:data`, интерфейс `MissionDefinition` в новом `:feature:missions:api`.
**Приёмка:** схема `4.json`, тест миграции 3→4; неизвестный тип/мусор в колонках не роняет список и звонок; модули без Android-зависимостей.
**Тесты:** unit, migration.

### M5-T02 — Math
**Приёмка:** уровни 1–5, ответ целый и положительный, без повторов подряд, свойства на 10 000 seed; `normalize` чинит некорректный конфиг.
**Тесты:** unit.

### M5-T03 — Сервис 🔔
**Приёмка:** `startMission` → 30 %, вибрация на паузе; касание продлевает; 15 с тишины → 100 % + сигнал сброса; UI исчез → 100 % сразу; `ACTION_DISMISS` (в т.ч. из уведомления) с миссией отклоняется, кнопки «Отключить» в уведомлении нет; без миссии поведение как в M4; `attenuate` не ломает FR-RING-8.
**Тесты:** Robolectric (service), unit.

### M5-T04 — Экран Math и хост 🎨🔔
**Приёмка:** прогресс «2/5», клавиатура (зоны ≥ 56 dp), неверный ответ — тряска + haptic, сброс ввода по сигналу; Back возвращает на звонок; Home → экран возвращается ≤ 3 с (с overlay); успех → отключение; тёмная тема, RU+EN, fontScale 2.
**Тесты:** Compose UI, Robolectric.

### M5-T05 — Редактор и превью 🎨
**Приёмка:** строка «Миссия» за флагом → выбор Math, уровень, количество, сводка; «Превью» запускает ту же миссию без звука с кнопкой «Закрыть»; результат через `BalarmNavState`; при выключенном флаге секции нет, сохранённая миссия не теряется.
**Тесты:** unit VM, Compose UI.

### M5-T-test
Сценарии: R16, R17, R3 (smoke), R1; E2E: создать с Math → сработал → отключён. Один прогон на API 37.

## Добавлено по ходу
* T04: при Home/Recents во время миссии сессия завершается (сервис на `MISSION_HIDDEN`), прогресс теряется — расходится с ADR-019 §6 (решённые задачи сохраняются); безопаснее для отключения — поправить ADR в T-docs. Отличия от ADR-019: нет `idleDeadline` (полоска бездействия считается на UI), вместо `screenVisible` — `missionScreenHidden()`, команды идут интентами. Клавиша «−» не нужна (ответы положительные). Возврат экрана после Home: `RingingService.scheduleScreenReturn` (1 с, при overlay). Визуальная проверка (fontScale 2, 360dp) — в T-test.
* T05: настройка миссии — подэкран внутри редактора (черновик в VM), отдельной записи навигации нет; без `MissionSettingsRoute` и результата через `BalarmNavState`; у превью — `MissionPreviewKey`. Править ADR-018 §6–7 и ADR-009 в T-docs; `RadioRow` (designsystem) → alarmy-ui. Визуальная проверка подэкрана/превью (fontScale 2, 360dp) — в T-test.
