# implement-task

## Предусловие
Найди `docs/milestones/M*.md` со статусом `In progress`. Если такого нет — **остановись** и предложи `/plan-milestone`. Задачи из плана в статусе `Planned` (не утверждён) не реализуются.

## 1. Выбор задачи
`$ARGUMENTS` или первая незакрытая задача, у которой выполнены все зависимости. Покажи пользователю в одной строке, что берёшь.

## 2. Контекст
Прочитай описание задачи, связанные FR в `docs/PRD.md`, релевантные ADR, существующий код затрагиваемых модулей. Для API Android/библиотек, в которых не уверен, — context7.

## 3. Реализация
* Следуй `CLAUDE.md` и архитектуре модулей (PRD §6.2).
* UI — по скиллу `alarmy-ui` (токены, компоненты).
* Задачи с меткой `🎨 ui` (экраны, компоненты `:core:designsystem`, навигация) делегируй агенту **ui-developer**; смешанные задачи — сначала логика/данные сам, затем UI агенту с готовыми контрактами.
* Если задача 🔔 reliability — сверься с инвариантами из агента architect (setAlarmClock, directBootAware, device-protected storage, FGS).
* Вне скоупа задачи ничего не меняй; найденное — добавь в «Добавлено по ходу» плана.

## 4. Тесты
Напиши тесты, перечисленные в задаче. Прогони:
```bash
./gradlew :<module>:testDebugUnitTest   # или test для JVM-модулей
./gradlew lint detekt ktlintCheck
```
Все должны быть зелёными. Если красные — чини, а не отключай.

## 5. Ревью
Вызови агента **reviewer** на диф задачи. Исправь 🔴 и 🟡 (или обоснуй пользователю, почему нет). Для 🔔 reliability-задач дополнительно вызови **tester** на соответствующие сценарии R*.

## 6. Завершение
* Отметь `[x]` в плане, критерии приёмки — галочками.
* Предложи сообщение коммита: `M<N>-T<NN>: <кратко>` (коммитить — только если пользователь попросил).
* Кратко отчитайся: что сделано, какие тесты, что осталось/вопросы.
